# Heptapod B 고해상도 스틸 재생성 계획

작성: 2026-09-08. 공식 문서 확인: 2026-09-07~08. 상태: 계획만 작성. 이미지 생성, 에이전트 실행, fal.ai 호출 없음.

## 1. 목표와 완료 조건

현재 승인된 스토리, 구도, 인물, 공간, 행동 단계를 보존하면서 스틸 이미지의 해상도와 사실적인 시네마틱 색감을 개선한다. 스틸 재생성을 먼저 완료한 뒤 기존 서브 영상 8개를 같은 순서와 요청 길이로 재생성한다.

이번 단계의 산출물은 계획과 실제 입력 파일 매핑이다. 실행 단계의 첫 산출물은 기준 스틸 2장, 이후 전체 고유 입력 스틸 12장이다. 콘티 HTML에 내장된 미리보기 JPEG 24장은 재생성 원본으로 사용하지 않는다.

스틸 최종 목표는 **3840×2160 PNG, 16:9**로 제안한다. 사용자가 픽셀 수를 명시한 것은 아니므로 이는 계획의 제안값이다. 크기만 늘린 파일을 생성 모델의 고해상도 결과라고 기록하지 않는다. 생성 도구가 반환한 원본의 크기, 형식, 파일 해시를 기록한다.

합격 조건:

- 고유 입력 12장 모두 원본과 출력 파일, 프롬프트, 참조 역할, 검수 결과가 연결됨.
- 모든 출력이 목표 픽셀 크기를 충족하고 100% 확대에서 의복, 난간, 선체와 암부 재질이 개선됨.
- 시점, 프레이밍, 비행체·리프트·개구부·접촉면의 위치와 규모, 인물 수·포즈·장비를 보존함.
- 외부와 내부의 서로 다른 광원 조건을 유지하면서 공통 색감이 이어짐.
- 클립 경계의 이미지 쌍을 대조하고 연결이 가능한 상태임.
- 기존 채택본은 유지하고 새 버전을 별도 경로에 저장함.

## 2. OpenAI 공식 문서 재검토

### 확인한 사항

1. 기존 이미지의 구도를 유지하는 이번 작업은 참조 없는 새 생성보다 **이미지 편집**으로 설계한다. 공식 Image API는 생성과 편집을 구분한다.
2. `gpt-image-2`는 입력 이미지를 항상 높은 충실도로 처리하므로 `input_fidelity`를 별도로 전달하지 않는다.
3. `size`와 `quality`는 별개다. API에서 `size="3840x2160"`, `quality="high"`를 지정하는 것과 프롬프트에 “4K”를 쓰는 것은 다르다.
4. 가이드는 3840×2160을 지원 크기로 제시한다. 단, 2560×1440보다 픽셀 수가 큰 결과는 실험적이다.
5. 입력 충실도가 높아도 이미지 간 인물 일관성과 정밀한 배치가 보장되지는 않는다. 구도 보존은 프롬프트와 결과 검수로 확인한다.

출처: [Image generation guide](https://developers.openai.com/api/docs/guides/image-generation), [GPT Image 2 model](https://developers.openai.com/api/docs/models/gpt-image-2).

### 프롬프트에 반영할 사항

참조 이미지마다 역할을 지정하고, 변경할 항목과 보존할 항목을 구분한다. 사실적 표현은 재질·광원·표면 반응으로 구체화하며, 반복 수정 때도 보존 조건을 다시 넣는다. 이번에는 원본 이미지가 구도와 피사체의 기준이고, 새 기준 이미지는 색감과 재질 표현만 전달한다.

출처: [GPT Image prompting guide](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide).

### 문서 간 차이 처리

공식 API reference의 일부 size enum은 이전 세대의 세 가지 크기만 표시한다. 반면 최신 모델 가이드는 유연한 해상도와 UHD를 명시한다. prompting guide에도 최대 변 길이의 `<3840`와 UHD 예시가 함께 나타난다. 계획은 최신 image-generation 가이드의 `<=3840`와 UHD 명시를 따른다. 실제 호출에서 거절되면 오류를 남기고 실행 경로를 재검토한다. 다른 비율로 조용히 낮추지 않는다.

참고: [Create image edit reference](https://developers.openai.com/api/reference/resources/images/methods/edit).

## 3. 실제 실행 도구와 해상도 처리

기본 경로는 현재 세션의 **내장 image_gen 편집 도구**다. 이 도구에는 prompt와 참조 이미지 입력이 있지만 API의 `size`, `quality`, 모델 선택 인자가 노출되어 있지 않다. API 문서의 파라미터를 내장 도구에 전달했다고 표현하면 안 된다.

기본 실행 절차:

1. 원본 로컬 PNG를 `view_image`로 확인한다.
2. 해당 원본을 edit target으로 명시하고, 필요한 기준 이미지에는 style-only 역할을 부여한다.
3. 한 호출에 한 장만 생성한다. 콜라주나 멀티패널로 여러 스틸을 만들지 않는다.
4. 프롬프트에 단일 가로형 UHD 스틸 의도를 명시한다.
5. 생성 도구 반환 원본을 프로젝트에 복사하고 실제 크기를 검사한다.
6. 기준 2장에서 해상도와 구도 보존이 확인된 뒤 나머지를 진행한다.

**해상도 미달 시:** 고해상도 합격으로 처리하지 않으며 나머지 10장에 같은 호출을 반복하지 않는다. 정확한 API 파라미터가 필요해지면 별도 OpenAI Images API/CLI 경로를 제안한다. 이 경로는 사용자가 선택한 뒤 실행하며, fal.ai 영상 호출에 대한 의도만으로 OpenAI 유료 API 경로까지 선택했다고 간주하지 않는다.

API 경로를 선택했을 때의 설정 계약:

```json
{
  "endpoint": "/v1/images/edits",
  "model": "gpt-image-2",
  "size": "3840x2160",
  "quality": "high",
  "output_format": "png",
  "n": 1
}
```

이는 내장 도구 호출 인자가 아니다. `input_fidelity`는 넣지 않는다. 실행 시 설치된 imagegen 스킬의 공식 CLI를 사용하고 별도 SDK 러너를 만들지 않는다. API 키는 환경에서만 읽는다.

관련 로컬 지침: [imagegen SKILL.md](/Users/ddd/.codex/skills/.system/imagegen/SKILL.md). “Do not switch to CLI fallback for ordinary quality, size, or file-path control.” 이 규칙 때문에 단순히 4K가 필요하다는 이유만으로 유료 API 경로를 자동 선택하지 않는다. 현재 계획 작성은 이 선택에 의존하지 않는다.

## 4. 실제 재생성 대상

정확한 원본 경로, SHA-256, 사용 클립, 보존할 영상 프롬프트는 [still-remaster-manifest.json](./still-remaster-manifest.json)에 기록했다. 실제 파일 해시 및 디코딩한 RGB 픽셀 기준으로 고유 입력은 12장이다. 기존 원본 크기는 1672×941 또는 1916×1080이다.

| 스틸 | 내용 | 사용 위치 | 담당 |
|---|---|---|---|
| K01 | 외부 비행체 원경 | C01 시작 | A |
| K02 | 하부 개구부 형성 | C01 끝, C02 시작 | A |
| K03 | 입구·리프트 목표 이미지 | C02 끝 | A |
| K04 | C02 영상에서 추출한 실제 끝 상태 | C03 시작 | root 기준 이미지 |
| K05 | 어둠 진입 목표 이미지 | C03 끝 | B |
| K06 | C03 영상에서 추출한 실제 끝 상태 | C04 시작 | B |
| K07 | 상승 목표 이미지 | C04 끝 | B |
| K08 | C04 영상에서 추출한 실제 끝 상태 | C05 시작 | B |
| K09 | 멀리 있는 천장 접촉면 | C05 끝, C06 시작 | B |
| K10 | 착륙 직전 이미지 | C06 끝 | root 기준 이미지 |
| K11 | 착륙 직전, 다음 클립의 실제 입력 버전 | C07 시작 | C |
| K12 | 벽을 향해 걷는 이미지 | C07 끝, C08 시작 | C |

K03/K04, K05/K06, K07/K08, K10/K11은 비슷한 시점이어도 다른 입력이다. 파일 이름이나 Shot 번호만으로 합치지 않는다. 같은 입력을 공유하는 K02·K09·K12는 한 번만 재생성하고 같은 출력 파일을 재사용한다.

현재 원본의 화면비는 정확한 16:9와 소폭 다르다. UHD 변환 시 주요 피사체를 자르거나 늘이지 않는다. 가장자리의 미세한 프레이밍 차이까지 원본 대비로 확인하고, 필요하면 이 차이를 별도 기록한다.

## 5. 룩과 보존 계약

고정하는 내용:

- 원본 시점, 카메라 높이와 기울기, 원근, 프레이밍, 장면 진행 단계.
- 원본에서 보이는 인물 수와 배열. 원경의 작은 인물을 확대하거나 새로 추가하지 않음.
- 회색 보호복과 장갑·신발·케이스, 리프트 구조와 난간.
- 선체의 무광 표면, 개구부 형상, 공간 규모, 접촉면의 위치·크기.
- 걷기 전/후 상태, 중력 전환 전/후의 기준면.
- 원래의 조명 방향, 광원의 수, 공간의 어두움과 안개의 깊이.

개선하는 내용:

- 회색 보호복이 녹색으로 물들지 않도록 중성에 가까운 재질색을 확보한다.
- 외부는 흐린 날 자연광과 녹회색 환경, 내부는 차가운 반사광과 청회색 암부를 유지한다.
- 하이라이트가 부드럽게 밝아지는 톤, 읽을 수 있는 암부, 자연스러운 국소 대비를 만든다.
- 실제 직물의 결·주름·솔기, 거친 무광 선체, 금속 난간의 절제된 표면 반응을 표현한다.
- 낮은 해상도의 번짐·압축 흔적을 디테일로 재구성한다. 과한 샤프닝 테두리나 강한 필름 입자로 선명함을 가장하지 않는다.

이미지 재생성은 원본에 없던 미세 정보를 추론한다. 원래 촬영된 정보를 복원했다고 주장하지 않는다. 광원·시간대·세트 디자인을 새로 만드는 프롬프트도 넣지 않는다.

### 편집 프롬프트 계약 초안

```text
Task: Edit Image 1 into a high-resolution photorealistic cinematic still.
Image 1: the exact approved shot to preserve, and the sole authority for
composition, camera, geometry, character placement, pose and story state.
Image 2, if supplied: the selected remaster reference for color response,
material realism and tonal treatment only. Do not transfer its composition.

Change only the rendering detail and color treatment. Preserve the exact
viewpoint, framing, object scale, silhouettes, positions, visible people,
wardrobe, lift rails, equipment, aperture and contact-surface geometry of
Image 1. Preserve its existing light sources and atmospheric depth.

Render believable fabric weave and seams, matte rough surfaces and restrained
metal reflections at the scale actually visible in this shot. Use natural
cinematic tonal separation, neutral pale-grey protective fabric, controlled
green-grey or blue-grey surroundings, readable shadows and soft highlight
roll-off. Keep the original scene's dark or bright exposure relationship.

Output one full-bleed widescreen still intended for 3840x2160 delivery.
No collage, border, text, new objects, redesigned architecture, added lights,
changed poses, orange/red suit recoloring, glossy CG surfaces, sharpening
halos, excessive grain or invented action.
```

각 호출에는 해당 스틸의 원본 경로와 보존 조건을 추가한다. 프롬프트의 목표 해상도 문장은 API의 실제 size 설정을 대체하지 않는다. 기준 이미지 없는 첫 호출에서는 Image 2 문장을 제거한다. 이후 호출은 원본과 확정된 기준 이미지를 직접 사용하고, 이전 변형 결과를 연쇄적으로 계속 편집하지 않는다.

## 6. 병렬 실행 설계

결정: **기준 스틸 2장은 순차 처리하고, 기준 확정 후 장면군 3개를 병렬 처리한다.** 전체 유효 동시성은 root 포함 4명이다. 각 작업자는 한 번에 이미지 한 장을 생성한다. root는 공유 매니페스트와 검수 문서를 소유한다.

병렬화 이유는 원본·룩·출력 계약이 확정된 뒤에는 스틸별 출력 파일이 독립적이기 때문이다. 기준 없이 처음부터 장면군을 나누면 서로 다른 색감과 재질이 생길 수 있다.

| 작업 | 담당 / 타입 | 범위 | 의존 | 산출물 | 완료 검사 | 주요 위험 |
|---|---|---|---|---|---|---|
| P0 | root | 원본 확인, 대상·룩·해상도 계약 | 없음 | 입력 매니페스트 | 12장·15개 입력 슬롯 연결 | 비슷한 원본의 잘못된 중복 제거 |
| P1 | root | K04 기준 편집 | P0 | K04 v001, 실제 크기, 비교 | 리프트·인물·입구 구도와 재질 | 고해상도 미달·포즈 변화 |
| P2 | root | K10 내부 기준 편집 | P1 룩 확정 | K10 v001, 실제 크기, 비교 | K04와 같은 재질색, 내부 광원 보존 | 하이라이트·암부 손실 |
| A | worker | K01–K03 외부 | P1·P2 통과 | PNG 3장 + 작업 기록 | 원경 규모, K03/K04 연결 | 선체 크기·하늘색 변화 |
| B | worker | K05–K09 진입·상승 | P1·P2 통과 | PNG 5장 + 작업 기록 | 수직축, K05/K06·K07/K08 연결 | 천장이 정면 벽으로 바뀜 |
| C | worker | K11–K12 착륙·접촉 | P1·P2 통과 | PNG 2장 + 작업 기록 | K10/K11 연결, 보행 단계 | 접촉벽 축소·새 동작 |

| V | 후속 root | fal.ai 규격 준비 | J | 8개 영상 호출 규격 | 길이와 시작·끝 매핑 보존 | 새 모델 스키마·영상 경계 변화 |

Wave 0: P0 완료. 현재 입력 매핑은 작성되어 있다.

Wave 1: K04를 먼저 생성해 원본 보존과 해상도 가능성을 확인한다. 이어 K10을 생성해 같은 재질이 내부 조명에서도 유지되는지 확인한다. 두 장이 목표를 충족해야 다음 wave가 열린다. 룩 선택이 필요한 비교 결과는 원본과 나란히 사용자에게 제시한다.

Wave 2: A·B·C가 동시에 수행한다. root는 생성하지 않고 도착한 파일의 실제 크기·해시를 확인하고 비교 콘티 및 통합 검수를 진행한다. 작업자별 출력 기록만 읽고 공유 manifest는 root만 갱신한다.

Wave 3: 경계 4쌍과 전체 12장을 검수한다. 문제 있는 스틸만 원본에서 다시 편집하고 재검수한다. 기준 룩 자체를 바꿀 경우 파생 작업을 멈추고 영향 범위를 표시한다.

## 7. 위임 가능한 작업 지시문

다음 지시문은 실행 단계용이다. 계획 작성 단계에서 에이전트를 생성하지 않는다.

### A / exterior

목적: 승인된 원본 K01·K02·K03을 확정된 룩으로 편집해 외부 스틸 3장을 완성한다. 외부 규모·자연광 처리를 독립적으로 소유한다.

입력: `docs/heptapod-b-encoder/remaster/still-remaster-manifest.json`, 이 계획의 보존 계약, root가 확정한 K04·K10과 look-contract. P1·P2가 통과한 뒤 시작한다.

소유: `output/heptapod-remaster/stills/K01-*`, `K02-*`, `K03-*`, `output/heptapod-remaster/reports/exterior.json`. 다른 파일은 쓰지 않는다. 특히 원본, 공유 manifest, 기준 이미지, 앱 코드는 변경하지 않는다.

수행: 각 edit target을 view_image로 읽고 내장 image_gen으로 한 장씩 편집한다. 원본은 구도 기준, 기준 스틸은 색감·재질 참고로만 사용한다. 실제 반환 파일을 소유 경로에 복사한다.

완료: 3개 출력의 실제 크기 검사, 원본과 인물·선체·리프트 대조, K03/K04 연결 검수 결과를 반환한다. root가 결과를 소비하고 선택한다.

제약: 공유 작업 공간에 다른 에이전트가 있다. 다른 사람의 변경을 되돌리지 말고 현재 파일에 맞춰 작업한다. 브라우저 자동화, fal.ai 호출, API/CLI 자동 전환, 임의 리사이즈 금지. 각 스틸은 첫 생성 1회와 원인이 분명한 수정 1회까지 수행하고, 계속 실패하면 root에게 반환한다.

인계: asset_id, 입력·출력 경로, 참조 역할, 최종 프롬프트, 실제 width/height, 생성 도구, SHA-256, 검수 결과와 미해결 항목을 JSON으로 제출한다.

### B / ascent

목적: K05–K09를 편집해 어둠 진입부터 먼 천장까지의 스틸 5장을 완성한다. 수직축과 먼 목적지의 크기 변화가 핵심이다.

입력·의존: 동일 manifest와 보존 계약, 확정 K04·K10 및 look-contract. P1·P2 완료 후 시작한다.

소유: `output/heptapod-remaster/stills/K05-*`부터 `K09-*`, `output/heptapod-remaster/reports/ascent.json`. 원본·다른 작업자의 이미지·공유 manifest·앱 코드는 변경하지 않는다.

수행: 원본을 각각 view_image로 읽고 내장 image_gen으로 개별 편집한다. K05/K06과 K07/K08을 독립된 원본으로 유지한다. 앞서 생성한 장면의 구도를 다음 장면에 복사하지 않는다.

완료: 5장의 실제 크기, 난간·인물·상승 시점 보존, 멀리 있는 접촉면 규모, 경계 2쌍의 연결 결과를 root에게 제출한다.

제약: 다른 에이전트와 작업 공간을 공유한다. 다른 변경을 되돌리지 않는다. 브라우저 자동화·fal.ai·API/CLI 전환·임의 리사이즈 금지. 각 스틸의 첫 생성 1회와 구체적 수정 1회 이후에도 미달이면 중단해 보고한다.

인계: A와 동일한 JSON 필드, 추가로 각 스틸의 천장/벽 방향 및 접촉면의 상대 크기 검수 기록.

### C / contact

목적: K11·K12를 편집해 착륙과 첫 보행 스틸 2장을 완성한다. 내부 접촉벽과 연구원의 재질색을 K10에 맞춘다.

입력·의존: 동일 manifest와 보존 계약, 확정 K04·K10 및 look-contract. P1·P2 완료 후 시작한다.

소유: `output/heptapod-remaster/stills/K11-*`, `K12-*`, `output/heptapod-remaster/reports/contact.json`. 원본·K10·공유 manifest·앱 코드는 변경하지 않는다.

수행: 원본을 각각 view_image로 읽고 내장 image_gen으로 편집한다. K11은 보행 전, K12는 보행 시작 상태를 유지한다. 접촉벽의 위치와 폭을 바꾸지 않는다.

완료: 2장 실제 크기, K10/K11 연속성, 네 사람과 장비·보행 단계, 접촉벽 명암을 검수해 root에게 반환한다.

제약: 다른 에이전트와 작업 공간을 공유한다. 다른 변경을 되돌리지 않는다. 브라우저 자동화·fal.ai·API/CLI 전환·임의 리사이즈 금지. 첫 생성 1회와 구체적 수정 1회 후에도 미달이면 root에게 반환한다.

인계: A와 동일한 JSON 필드, 추가로 보행 단계와 K10 대비 벽·의복의 색감 검수 기록.

## 8. Root의 통합·검수 책임과 실패 처리

- 입력 및 기준 이미지의 역할을 명확히 지정하고 프롬프트 버전을 고정한다.
- 출력의 실제 크기와 해시를 직접 확인한다. 도구가 노출하지 않는 모델명·quality 설정은 추정해 기록하지 않는다.
- 원본과 같은 화면 크기로 비교해 구도·실루엣·랜드마크를 확인하고, 별도로 100% 확대해 실제 디테일을 검사한다.
- 변경 허용 영역이 색감·재질이므로 전체 픽셀 MSE를 합격 기준으로 삼지 않는다. 구조·의미 검수와 광원·색감 검수를 분리한다.
- 공유 K02·K09·K12는 호출마다 새로 만들지 않고 선택된 동일 파일을 연결한다.
- K03/K04, K05/K06, K07/K08, K10/K11의 차이가 원래 있었던 차이인지 새로 생긴 오류인지 대조한다.
- root만 `look-contract.json`, 선택 manifest, 검수 HTML을 작성한다. 출력 경로 중복이 발견되면 파일을 덮어쓰지 않고 담당자에게 되돌린다.
- 개별 실패는 해당 스틸만 재시도한다. 동일 오류로 자동 반복하지 않는다. 과도한 변경이 필요한 후보는 탈락시키고 원본으로 돌아간다.
- 동시 생성이 불가능하거나 rate limit이 발생하면 같은 계약으로 A→B→C 순차 수행한다. 공유 결과나 기준을 바꾸지 않는다.
- 해상도 때문에 막힌 경우 먼저 출력 미달을 보고하고 경로를 선택한다. 목표를 2560×1440으로 낮추거나 API 경로를 여는 선택은 사용자에게 실제 파일과 함께 제시한다.

결과 검수는 파일 직접 검사와 이미지 뷰어로 수행한다. 브라우저 자동화는 사용하지 않는다.

## 9. 후속 영상 계획

스틸 검수가 끝난 뒤에만 fal.ai 영상 단계로 진행한다. 이 단계에서는 현행 fal.ai 모델 스키마, 요청 해상도 및 계정 사용 가능 여부를 다시 확인한다. 고해상도 입력이 곧 고해상도 출력 영상을 보장한다고 가정하지 않는다.

| 클립 | 구간 | 요청 길이 | 시작 | 끝 |
|---|---|---:|---|---|
| C01 | 01→02 | 4초 | K01 | K02 |
| C02 | 02→03 | 8초 | K02 | K03 |
| C03 | 03→05 | 5초 | K04 | K05 |
| C04 | 05→07 | 6초 | K06 | K07 |
| C05 | 07→09 | 6초 | K08 | K09 |
| C06 | 09→10 | 6초 | K09 | K10 |
| C07 | 10→11 | 6초 | K11 | K12 |
| C08 | 11→화면 채움 | 6초 | K12 | 없음 |

7개는 시작·끝 이미지 기반, 마지막은 시작 이미지만 사용하는 기존 방식을 유지한다. 기존 모델·duration·cfg_scale·오디오·동작 프롬프트를 보존하며, 새 이미지의 색감과 충돌하는 색감 문장만 추후 변경 내역을 남겨 조정한다. 카메라·행동 지시를 새로 쓰지 않는다.

원래 C03·C04·C05는 앞 영상의 실제 끝 프레임을 입력으로 사용했다. 새 영상에서도 이 연속성을 검수해야 한다. 따라서 첫 영상 배치는 전부 무조건 병렬 호출하지 않고, 우선 C01·C02를 확인한 뒤 새 끝 상태와 K04의 연결 여부를 검사한다. 이어 C03→K06, C04→K08 경계도 확인한다. 연결이 맞지 않으면 다음 호출 전에 해당 입력 스틸을 조정한다. 저해상도 영상 끝 프레임을 4K 스틸이라고 대체하지 않는다.

요청 길이 합은 47초다. 기존 합본 실측 47.081초는 인코딩·컨테이너 기준 수치이며 새 생성의 동일 소수점 길이를 보장하지 않는다. 최종 편집에서는 기존 컷 타이밍과 목표 재생 길이에 맞춰 검증·컨폼한다. 새로운 움직임의 픽셀 단위 동일성은 생성 모델 특성상 보장하지 않는다.

## 10. 이번 작성 결과

- 12개 고유 스틸의 경로·해시·크기·소유자·사용처를 기록한 manifest.

생성 호출 및 에이전트 위임은 아직 수행하지 않았다. 현재 요청을 계획 설계로 해석했기 때문이다.
