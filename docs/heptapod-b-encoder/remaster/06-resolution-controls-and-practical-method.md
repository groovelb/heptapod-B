# 내장 이미지 도구: 파라미터·프롬프트·출력 크기 검증

확인일: 2026-09-08. 사용 조건: Codex 내장 image_gen, 추가 이미지 API 호출 없음. 이번에 기존 K04 원본을 참조한 내장 편집 호출 2회를 실시했다. 완성본 교체나 영상 생성은 하지 않았다.

## 1. 특정 파라미터가 있는가

현재 호출 규격은 prompt, referenced_image_paths, num_last_images_to_include다. 설치 버전 0.153.4의 공식 구현은 생성·편집 모두 size와 quality를 auto로 설정한다. 알려지지 않은 인자는 거부한다. size, resolution, quality를 추가하거나 환경변수에 임의 값을 넣는 방식은 지원된 제어법이 아니다.

[공식 구현](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/ext/image-generation/src/tool.rs#L469-L477), [명시적 파라미터 요청 이슈](https://github.com/openai/codex/issues/20839).

## 2. 프롬프트로 해결되는가

이번 실험은 동일 원본과 동일 문장을 사용하고 픽셀 숫자만 바꿨다. 두 조건 각각 1회이며 생성 변동성이 있으므로 성공률을 추정하는 실험은 아니다. 원본 PNG의 IHDR을 읽어 치수를 검증하고 파일을 변경 없이 복사했다.

| 방식 | 요청 | 실제 반환 | 정확한 크기 충족 |
|---|---|---|---|
| 짧은 명령, 픽셀 크기를 첫 문장에 기재 | 2048×1152 | 1672×941 | 실패 |
| 같은 짧은 명령, 픽셀 크기만 변경 | 3840×2160 | 1672×941 | 실패 |
| 앞선 긴 UHD 명령, 첫머리와 마지막에 크기 반복 | 3840×2160 | 1672×941 | 실패 |

짧은 명령의 공통 내용은 네이티브 지정 픽셀 크기, 전체 구도와 인물·리프트 보존, 실사 시네마 색보정, 새로 해상된 의복·금속 세부 표현이다. 프롬프트와 원본 반환 경로는 `output/heptapod-remaster/reports/resolution-prompt-probes-results.json`에 저장했다.

실험 결과는 이번 세 프롬프트 형태가 해상도를 강제하지 못했다는 뜻이다. 모든 가능한 자연어 방식이 불가능하다는 증명은 아니다. 다른 안내가 4K 문구를 추천한다고 해서 검증된 출력 방식으로 취급하지 않는다.

## 3. 딱 지원되는 해상도 목록이 있는가

[Codex 제품 안내](https://learn.chatgpt.com/docs/image-generation)에는 내장 도구의 보장된 픽셀 출력 목록이 없다. 1672×941는 현재 관찰값이며 선택 가능한 공식 프리셋이 아니다. 1024×1024, 1536×1024, 2048×2048, 3840×2160 등의 다른 인터페이스·도구 목록을 현재 내장 호출의 지원 목록으로 가져오지 않는다.

원하는 숫자를 여러 개 대입해 지원 목록을 추측하는 반복 생성도 현재 증거상 효율적인 접근은 아니다.

## 실용적 선택: 단일 출력과 최종 마스터 제작을 구분

현재 내장 단일 호출만으로 정확한 UHD를 안정적으로 만드는 방법은 확보하지 못했다. 가장 근거가 있는 다음 검증 후보는 **내장 모델로 작은 영역의 세부를 재생성하고 로컬에서 정확한 크기의 전체 영상용 마스터로 합성하는 방식**이다.

[공개 구현](https://github.com/xuanyidesign/codex-image-optimize-4k-upscale/blob/main/SKILL.md)은 겹치는 영역 재생성, 위치 정렬, 신뢰 가능한 고주파 세부 합성을 기술한다. 그 구현의 품질을 이 프로젝트에서 검증한 것은 아니다. 단일 네이티브 UHD 출력이나 원본에 실제 없던 세부의 복원 보장으로 표현하지 않는다.

이 프로젝트용 검증 설계:

1. 전체 구도·인물·광원은 승인 원본을 기준으로 고정한다. 목표 3840×2160에서 가장자리를 잘라 비율을 맞추지 않으며, 원본 1916×1080과 16:9의 미세한 차이는 실제 비율 보존 또는 소폭 비율 조정 중 구현 시 명시해야 한다.
2. 3×3 영역으로 나눈다. 3840×2160 기준 중심 영역은 1280×720이고, 좌우 각 128px·상하 각 72px의 문맥을 포함하면 내부 영역의 요청 범위는 1536×864다. 바깥 가장자리에는 실제 이미지 범위만 사용한다. 이 계산은 작업 좌표이며 생성기 지원 프리셋이 아니다.
3. 각 영역은 같은 전체 색보정 기준을 참조해 내장 모델로 재생성한다. 반환 치수가 해당 최종 영역보다 작은 경우 기록하고 재확대에 의존하는 정도를 평가한다.
4. 인물 윤곽·기계 구조·위치·명암은 전체 기준 영상에서 유지한다. 각 결과를 위치 정렬한 뒤 신뢰할 수 있는 세부만 합친다. 생성 영역의 전체 픽셀을 단순히 이어 붙이지 않는다.
5. 파일 치수, 접합부, 인물 수·윤곽, 리프트 교차 구조, 과장된 표면 질감, 원본 대비 세부 개선을 점검한다. 한 장이 통과해야 나머지 스냅샷에 적용한다.

이 방법에서 정확한 최종 파일 치수는 로컬 합성으로 결정할 수 있다. 시각적 세부 개선과 영화 컷의 연속성은 아직 검증해야 한다. 지금 시점에 '안정적인 고해상도 생성법을 완성했다'고 보고하지 않는다.
