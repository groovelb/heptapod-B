# 랜딩 스크럽 영상 재제작 병렬 오케스트레이션

작성: 2026-09-08. 상태: 설계 완료, 실행 전.

## 1. 목표와 실행 경계

현재 랜딩 영상의 스냅샷을 GPT Image 2, 2560×1440을 명시해 재생성하고, 같은 내용·인물·우주선·시간 구조의 영상으로 재제작한다. 샤프니스와 시네마틱 표현은 강화한다. 이번 산출물은 실행 설계이며 이미지 생성, 에이전트 실행, 영상 API 제출, 랜딩 교체는 수행하지 않는다.

권장 구조는 **공통 원본·룩 확정 → 장면군별 이미지 병렬 생성 → 전체 연속성 검수 → 동작 보존 파일럿 → 영상 병렬 제작 → root 단일 통합**이다. 최대 동시 에이전트는 root 포함 4개다. 단계 내부에서만 최대 3개 작업자를 사용한다.

사용자가 말한 ‘원본과 100% 동일’은 내용과 스토리텔링의 합격 조건이다. 생성 모델이 이를 자동 보장한다고 가정하지 않는다. 길이·프레임 수·순서·오디오·UI 시점은 기계적으로 고정하고, 외형·동작·공간 연속성은 원본과 대조해 통과시킨다. 미충족 결과를 성공으로 간주하지 않는다.

‘약 47초’나 8개 생성 요청의 길이를 더한 47초로 잘라 맞추지 않는다. 교체 대상인 웹 파일의 영상 PTS·1129프레임과 오디오 패킷 시간축을 보존한다. UI의 47.08을 임의로 47.09로 고치지 않는다.

소스 우선순위:

1. **현재 재생 중인 로컬 웹 MP4**: 실제 사용자에게 보이는 프레임·동작·시간의 기준. 실행 시작 때 경로와 해시를 다시 고정한다. 배포 서버와 동일한지는 이번 로컬 확인의 범위 밖이다.
2. **최종 편집 마스터**: 같은 PTS의 원본 프레임을 비교한 뒤, 웹 인코딩 이전의 이미지 추출 소스로 사용한다. 프레임 수 일치만으로 내용 일치를 가정하지 않는다.
3. **HTML의 24장**: 장면별 IN/MID/OUT 선택 지점과 검토 순서. JPEG 미리보기는 생성 입력으로 사용하지 않고 원본 MP4에서 같은 시점의 PNG를 추출한다.
4. **과거 고유 생성 입력 K01~K12**: 우주선·보호복·장비의 보조 레퍼런스. 현재 최종 컷과 다를 때는 현재 영상이 우선한다.
5. **과거 프롬프트**: 제작 의도를 이해하는 보조 자료. 프롬프트가 주장하는 동작을 실제 영상에 새로 추가하지 않는다.

기존 매핑은 `tmp/storyboard-audit/selected-cut-manifest.json`, `docs/heptapod-b-encoder/remaster/still-remaster-manifest.json`에 있다. K01~K12의 소스 파일은 이번 확인 시 모두 존재했다. 기존 remaster 작업물·manifest는 보존하고 새 실행 폴더를 사용한다.

## 4. 외형과 시네마틱 표현의 계약

### 원본에서 잠글 것

- 우주선: 동일 난형 실루엣, 종횡비, 무광 표면, 상대적 규모, 부유 높이, 개구부 위치·형태. 밝은 장식, 추가 패널, 새로운 엔진/조명 금지.
- 인물: 네 명의 연구팀이라는 원래 설정, 옅은 회색 보호복, 헬멧/바이저, 배낭형 호흡 장비, 검은 장갑·부츠. 원본에서 보이지 않는 얼굴이나 문양을 발명하지 않는다.
- 프레임마다 보이는 인원 수는 해당 원본의 가림과 화면 밖 이동에 맞춘다. 외부 원경의 지원 인력을 임의로 네 명으로 줄이거나, 가려진 팀원을 억지로 드러내지 않는다.
- 장비: 검은 산업용 리프트, 난간, 교차 구조, 장비 케이스의 수·위치·비율. 인물 T1~T4는 좌우 위치만으로 명명하지 않고 프레임 간 추적 근거와 불확실성을 기록한다.
- 공간/동작: 같은 개구부와 실내, 광원의 위치, 카메라 구도·축·화각·진행 경로, 인물 포즈·진행 방향·중력 전환의 타이밍.
- 원본의 의도된 가림·모션 블러·안개를 정체성 근거로 사용한다. 없는 얼굴 디테일을 ‘복원’하지 않는다.

### 강화할 것

- 원본에 존재하는 의복·금속·지면 세부의 분리감과 선명도.
- 원래 광원 방향을 따르는 절제된 명암 분리, 하이라이트 롤오프, 공간 깊이.
- 저채도 녹회색/청회색의 통일된 영화 색보정과 은은한 필름 질감.
- 큰 실루엣과 작은 인물 사이의 대비를 재질과 빛으로 강조하되 실제 크기는 바꾸지 않음.

극적 표현을 위해 새 앵글, 더 빠른 접근, 렌즈 변경, 과장된 롤, 번개, 새 광원, 강한 렌즈 플레어, 물체를 가리는 안개, 검게 뭉개진 암부를 추가하지 않는다. C08의 앱 접촉면 연결 색과 밝기는 별도로 잠근다. 충돌 시 이야기·정체성·시간 보존이 표현 강화보다 우선한다.

### 공통 레퍼런스 묶음

root가 실제 프레임과 원본 입력에서 우주선, 연구팀·리프트, 실내·접촉벽의 레퍼런스를 선별한다. 로컬 이미지 확인은 `view_image`로 수행한다. 색보정/룩의 기준과 외형 기준을 다른 역할로 지정한다.

각 생성 호출은 (1) 해당 시점 원본 PNG, (2) 장면에 필요한 고정 외형 레퍼런스, (3) 해당 환경의 확정 룩 샘플만 전달한다. 개구부 컷에 외부 우주선 전경의 구도를 복사하거나, 모든 컷에 같은 인물 포즈를 복사하지 않는다. 참조 이미지의 역할·우선순위를 프롬프트와 레코드에 명시한다. 편집 대상이 최우선이다.

## 5. 공통 이미지 프롬프트

다음 템플릿과 root의 잠긴 프레임별 사실을 조합한다. 작업자는 룩을 독자적으로 재설계하지 않는다.

```text
Use GPT Image 2. Generate this edited cinematic frame at exactly
2560×1440 pixels (2560 pixels wide and 1440 pixels high), landscape 16:9.
Request a higher-resolution image with sharper resolved photographic detail
and a more dramatic cinematic treatment.

Image 1 is the exact original frame to edit. It is authoritative for
composition, camera viewpoint, subject placement, pose, visible subject count,
occlusion, architecture, action state, and story content.
Images {identity_refs} define the SAME existing vessel, research team,
protective suits, helmets, breathing packs, lift and equipment when visible.
Image {look_ref} defines only the locked lighting treatment and color grade.
Do not copy its composition or introduce its subjects into Image 1.

Frame: {frame_id}, original PTS: {pts}, scene: {scene_id}.
Preserve these observed facts exactly: {locked_observed_facts}.
Preserve these silhouettes, placements and visible details: {identity_lock}.

Enhance existing material detail, controlled local contrast, cinematic
tonal separation, subtle film texture and atmospheric depth, following the
existing light direction and the approved desaturated green-grey/blue-grey
grade. Keep readable shadows and restrained highlights. Preserve intentional
motion blur, occlusion and fog. Keep the original smooth matte vessel surface.

The content and storytelling must remain 100% identical to the original.
Do not change identities, costumes, body proportions, poses, object count,
vessel shape, lift geometry, camera position, framing, perspective or action.
No new scene, no new objects, no invented face details, no orange/red suits,
no glowing vessel panels, no added lights, no hard sharpening halos, no HDR,
no text, no logo, no watermark. Return one full-bleed finished image.
```

모델명과 해상도 문구는 다음과 같이 운영한다.

- `GPT Image 2`와 `2560×1440`을 실제 전송 프롬프트에 반드시 포함한다.
- 내장 도구에는 현재 모델 선택·size의 독립 인자가 없으므로 문구만으로 설정을 강제했다고 기록하지 않는다.
- 실제 반환 치수를 저장한다. 해상도 미달만으로 중단하거나 반복하지 않고, 내용·외형이 합격하면 후보로 계속 진행한다.
- 생성 PNG를 원본 그대로 보관한다. 후처리 확대를 네이티브 고해상도 생성이라고 표현하지 않는다.

## 6. 산출물과 단일 작성자

실행 시 새 루트 `output/heptapod-remaster-v2/<run-id>/`를 만든다. 아래 경로는 이 실행 루트에 대한 상대 경로다.

| 경로 | 단독 작성자 | 내용 |
|---|---|---|
| `baseline/`, `refs/`, `locks/` | root | 원본 해시, PTS, 추출 PNG, 사건·외형·룩·경계 고정 |
| `manifest.json`, `decisions.md` | root | 채택본 등록, 버전과 의존 관계 |
| `stills/master/` | root | 24장 중 먼저 생성할 룩/외형 파일럿 3장 |
| `stills/A/`, `stills/B/`, `stills/C/` | 해당 이미지 작업자 | 소유 프레임, 프롬프트, 개별 report |
| `stills/boundaries/` | root | 영상 제작에 필요할 때만 추가하는 실제 경계 프레임 |
| `motion/A/`, `motion/B/`, `motion/C/` | 해당 영상 작업자 | 소유 클립의 후보·제출 기록·검증 |
| `qa/identity/`, `qa/motion/`, `qa/media/` | 해당 검수자 | 서로 다른 검수 범위의 읽기 전용 조사 결과 |
| `delivery/`, `review.html`, `rollback.json` | root | 최종 조립, 비교 페이지, 교체/복구 매핑 |

모든 report는 `id, source_path, source_sha256, source_pts, reference_paths_and_hashes, lock_version, prompt_path, tool, requested_dimensions, actual_dimensions, output_path, output_sha256, transformed_after_generation, checks, unresolved`를 포함한다. 생성 요청/영상 요청 식별자도 제공되는 경우 저장한다. 이미 생성된 동일 ID를 재개 시 중복 제출하지 않는다.

| J2 | root | 8클립 조립, 원본 오디오, 웹용 후보 | VA+VB+VC | 1129프레임, 원본 PTS, 경계와 소리 보존 | 합본 길이·A/V 어긋남 |
| QI | explorer | 완성본 외형 검수 | J2 | qa/identity, 위반 시점/영역/근거 | 암부에 가려진 변경 |
| QM | explorer | 완성본 사건·동작 검수 | J2 | qa/motion, 사건·전환·원본 비교 | 중간 프레임의 새 동작 |
| QT | explorer | 완성본 미디어/소비 계약 검수 | J2 | qa/media, PTS/fps/GOP/오디오/경로 | 스크럽 성능 저하 |
| R | root | 채택 결정과 향후 교체 | QI+QM+QT | 검수 통과, review, 복구 가능한 단일 교체 | 부분 교체/캐시 혼재 |

```text
P0 → P1 → [IA | IB | IC] → J1 → P2 → [VA | VB | VC] → J2
                                                        ↓
                                               [QI | QM | QT] → R
```

## 8. 단계 운영과 합류 조건

### Wave 0: 원본과 공통 기준 확정

root가 현재 원본을 해시로 고정하고 24개 선택 시점을 프레임 인덱스/PTS로 변환한다. 초 단위 seek의 반올림 결과를 가정하지 않는다. 원본 MP4의 대응 프레임과 동일한지 확인한다. 1129프레임 전체의 사건 진행은 검토용 자료로 확보한다.

P1은 순차 실행한다. 우주선 원경, 보호복·리프트가 보이는 컷, 중력 전환 컷이 모두 원본 외형을 보존해야 공통 룩을 잠근다. 외형은 원본에서 고정하고 새로운 파일럿 이미지의 우발적 변경을 이후 컷에 전파하지 않는다. 앞선 표지 파일럿은 차량과 안개가 재해석됐으므로 자동 채택하지 않는다.

### Wave 1: 21장 병렬 생성, root의 3장 재사용

A/B/C 각자는 자기 장면군에서 IN → MID → OUT 순서로 처리하며, 매 호출에 원본과 잠긴 레퍼런스를 다시 포함한다. 이전 생성 결과만 연쇄 참조하지 않는다. 총 기본 산출물은 24장이다. 영상 입력 K01~K12를 24장 대신 재생성했다고 보고하지 않는다.

동시에 root는 영상 경로의 로컬 실행기·지원 입력 형식을 조사하고 원본 오디오 패킷/타임라인 보존 방식을 준비한다. 이미지 작업자를 기다리면서 새 이미지 스타일을 만들지 않는다.

J1은 24/24 등록, 중복 ID 0, 전체 참조 해시/룩 버전 일치, 모든 인물·장비·우주선 비교 통과로 닫는다. 선명해도 외형이 다른 이미지는 탈락이다.

### Wave 2: 경계와 동작 보존 검증

24장은 리뷰 표본이며 영상의 모든 움직임을 규정하지 못한다. 각 컷의 IN/OUT은 경계 혼입 방지를 위해 약 0.16초 안쪽에서 뽑았으므로 실제 시작·끝 프레임 대신 사용할 수 없다.

root가 필요 시 각 컷의 실제 첫/마지막 프레임을 별도 B-ID로 추출·편집한다. 최대 16개 후보이며 동일 원본 프레임/역할은 중복 생성하지 않는다. 이전 컷의 마지막과 다음 컷 첫 프레임이 다르면 둘 다 유지한다. 과거 K03↔K04, K05↔K06, K07↔K08, K10↔K11도 서로 다른 이미지이므로 강제로 같게 만들지 않는다.

영상 경로는 **원본 클립의 프레임/동작을 조건으로 유지하면서 확정한 새 룩을 반영하는 방식**을 우선 검증한다. 특정 서비스가 이를 지원한다고 가정하지 않는다. 실제 사용 가능한 실행기와 인터페이스를 확인하고 `decisions.md`에 입력·제약·비용·동작 보존 증거를 기록한다.

기존 Kling 시작/끝 이미지 방식만 가능한 경우, 그 사실을 명시하고 C01·C06 파일럿에서 원본 동작을 재현하는지 먼저 판단한다. 새 스틸 2장과 동일 프롬프트만으로 중간 움직임이 100% 같다고 가정하지 않는다. 미달이면 영상 전체 병렬 제출을 시작하지 않는다. 24개 정지 이미지 슬라이드쇼도 대체 완성본으로 인정하지 않는다.

### Wave 3: 영상 3분할 병렬 제작

P2에서 확정된 동일 방식과 원본 사건 타임라인으로 VA/VB/VC를 실행한다. 서로의 최종 프레임을 기다려 다음 컷을 시작하는 체인 대신 root가 미리 잠근 경계 묶음을 공유한다. 다만 선택한 영상 경로가 앞선 결과를 필수 입력으로 요구하면 해당 연결만 순차화한다.

원본 오디오는 별도 보존한다. 생성된 새 오디오를 채택하거나 현재 비트 MP3·bed-loop를 재생성하지 않는다. 동작이 어긋난 후보를 시간 늘이기/줄이기로 통과시키지 않는다. 프레임 중복·삭제로 길이만 맞추는 것도 실패다.

### Wave 4: 조립, 독립 검수, 교체 준비

root는 승인한 클립만 원래 순서와 프레임 범위로 조립한다. 원본 웹 파일의 AAC 패킷을 보존해 재인코딩 없이 mux하고, stream/format duration과 시작 PTS를 다시 확인한다. 단순 `-shortest`로 오디오 꼬리를 자르지 않는다.

현재 웹 크기 1916×1080, 960×542와 GOP 6/CFR 24fps를 기본 전달 계약으로 유지한다. 2560×1440 생성 요청은 스틸 요청이며 자동으로 모바일 전달 크기를 올리지 않는다. 필요하면 2560×1440 마스터를 별도로 보관하되 실제 생성 치수와 인코딩 치수를 구분한다. 화면비 차이는 비율 보존 fit으로 처리하고 크롭·stretch·추가 여백 여부를 기록해 시야 손실을 검사한다.

`scripts/build-hero-scrub.mjs`는 원본 경로가 고정돼 있고 영상뿐 아니라 오디오 자산·타임라인도 다시 쓴다. 기존 명령을 그대로 실행하지 않는다. root가 staging 출력과 영상/포스터만 만들 수 있는 별도 실행 경로를 준비한다. 기능 변경 시 그때 적용되는 프로젝트 스킬을 읽는다.

QI/QM/QT는 완성된 후보가 나온 뒤 병렬 검수한다. root는 그동안 교체 파일 목록, 기존 해시, 새 해시, 캐시 갱신/복구 매핑을 준비한다. 소스 미디어와 기존 storyboard는 기록용으로 보존하고, 새로운 스토리보드는 새 영상에서 24장을 다시 추출한다. 옛 문서에 새 이미지를 넣고 ‘기존 최종 영상의 실제 프레임’이라고 표기하지 않는다.

## 9. 즉시 전달 가능한 작업자 브리프

아래 공통 브리프와 작업별 블록을 함께 전달한다. `{RUN}`과 manifest/lock 버전은 root가 실행 시작 시 실제 값으로 채운다.

### 공통

> 다른 에이전트와 같은 작업 공간을 공유한다. 소유 폴더만 작성하고 다른 사람의 변경을 되돌리지 말며 현재 상태에 맞춰 조정한다. shared manifest, 원본 미디어, public, src, 기존 remaster 폴더는 수정하지 않는다. root가 제공한 실행 루트·소스 해시·잠금 버전을 따른다. 브라우저/Playwright/Chrome MCP 자동화는 사용하지 않는다. 추가 하위 에이전트를 만들지 않는다. 인계는 생성/변경 경로, ID 목록, 실제 검사 결과, 미해결 문제, 재실행 필요 항목으로 반환한다. 외형 또는 이야기 위반을 발견하면 성공으로 표시하지 않는다.

### IA / worker

> 목표: C01~C03의 원본 시점에 대응하는 고해상도 편집 스틸을 만든다. 외부 비행체와 개구부 진입 구간을 한 소유자가 책임져 외형 변형을 줄인다. 입력: `{RUN}/manifest.json`, `locks/`, `refs/`, 해당 baseline PNG. 선행: P1 통과. 소유: `stills/A/**`만. root 소유 F01-IN/F02-MID는 읽기 전용 재사용하며 나머지 7장을 생성한다. 모든 호출에 GPT Image 2와 2560×1440을 명시한다. 파일별 실제 치수·해시·프롬프트·외형 검사 report를 반환한다. 완료: 7장과 report, 우주선·개구부·지원 인력·연구팀·리프트 원본 대조. 호출당 1장, 동시에 1건만 제출한다. 내용 교정은 이미지당 최초+최대 2회까지만 시도하고 미달은 root에 반환한다. 해상도 숫자만을 이유로 재시도하지 않는다. 소비자: J1/root.

### IB / worker

> 목표: C04~C06의 내부 상승·중력 전환 스틸을 원본과 동일한 공간/동작 상태로 만든다. 입력과 선행은 IA와 같다. 소유: `stills/B/**`만. root 소유 F06-MID를 재사용하고 나머지 8장을 생성한다. 완료: 8장과 report, 리프트 구조·인물 가림·카메라 축·접촉면 방향 대조. 보호복·장비 디자인을 A와 독립적으로 정하지 않는다. 중력 전환을 더 극적으로 보이게 하려고 롤 각도·몸 방향을 바꾸지 않는다. 해상도 문구·시도 상한·인계 규칙은 IA와 같다. 소비자: J1/root.

### IC / worker

> 목표: C07~C08의 하차·보행·접촉면 접근 스틸 6장을 만든다. 이 구간을 함께 소유해 보행과 마지막 화면 전환을 보존한다. 입력과 선행은 IA와 같다. 소유: `stills/C/**`만. 완료: 6장과 report, 인물 포즈·케이스·보행 시점·벽의 고정 위치·마지막 밝기/가림을 원본 대조. 인물을 임의로 지우거나 새 헵타포드·로그그램을 추가하지 않는다. 해상도 문구·시도 상한·인계 규칙은 IA와 같다. 소비자: J1/root.

### VA / VB / VC / worker, 각각 독립 인스턴스

> 목표: root가 지정한 C01~C03(A), C04~C06(B), C07~C08(C)만 원본과 같은 사건·동작·PTS로 제작한다. 소유: 각각 `motion/A/**`, `motion/B/**`, `motion/C/**`. 입력: 해당 원본 클립/프레임 범위, J1 채택 스틸, root 경계 묶음, P2에서 검증된 실행 명세와 event-lock. 선행: P2 통과와 실제 영상 실행 범위 확정. 목적: 공유 경계를 고정한 상태에서 독립 클립 제작 지연을 병렬화한다. 임의 모델 변경, 다른 클립 수정, 오디오 채택, 합본 조립 금지. 통과한 파일럿은 재생성하지 않는다. 완료: 원본 범위와 동일한 PTS/프레임 수, 사건·외형 검사 report, 제출 ID, 실패 시점. 각 클립 최초+교정 1회까지, 초과 시 중단해 root로 반환. 소비자: J2/root.

### QI / explorer

> 질문: J2 후보에서 우주선·연구팀·보호복·리프트·공간이 원본이나 인접 컷과 다른 시점은 어디인가? 미디어와 manifest는 읽기 전용. 소유: `qa/identity/**` report만. 24개 대응 프레임, 컷 경계 양쪽, 인물이 선명한 추가 프레임을 대조하고 전체 시퀀스의 변형을 검토한다. 위반마다 PTS·원본/후보 경로·영역·차이를 기록한다. 눈에 안 보이는 얼굴 정체성을 확인했다고 주장하지 않는다. 완료는 합격 또는 근거 있는 실패 목록이다. 선행 J2, 소비자 R/root.

### QM / explorer

> 질문: J2 후보의 사건·카메라 진행·중력 전환·보행·접촉면 진입이 원본과 같은 프레임 순서와 시점에 일어나는가? 소유: `qa/motion/**` report만. event-lock과 원본 전체 동작을 비교한다. 경계에서뿐 아니라 중간의 추가 동작·점프·벽 이동·사람 소멸을 찾는다. 24개 정지 프레임만 맞는다고 통과시키지 않는다. 완료는 사건별 원본/후보 PTS 대조와 실패 목록이다. 선행 J2, 소비자 R/root.

### QT / explorer

> 질문: J2 전달 파일이 현재 랜딩의 미디어/시간/스크럽 소비 계약을 충족하는가? 소유: `qa/media/**` report만. ffprobe/ffmpeg와 코드 읽기로 fps·1129프레임·PTS·stream/container duration·최대 GOP·해상도·SAR·오디오 패킷·포스터·파일 경로·용량·임의 시점 디코딩을 확인한다. UI 비트·셀 가중치·42초 자동재생·기존 MP3 해시가 보존됐는지 검사한다. 브라우저 실측은 수행하지 않고 미실시로 기록한다. 완료는 항목별 실제 수치와 실패 목록이다. 선행 J2, 소비자 R/root.

## 10. 합류, 실패 복구, 완료 판정

- root만 최종 결과를 채택한다. 작업자의 완료 메시지는 검증 대상이다. 소유 범위를 벗어난 변경은 diff로 검출하고 해당 작업자에게 범위 내 수정으로 돌려보낸다. 타인의 작업을 일괄 reset하지 않는다.
- 해상도 미달: 실제 크기를 기록하고 시각적 개선 검토를 계속한다. 이미 생성된 두 번의 표지 파일럿 모두 1672×941였으므로 이번 계획도 숫자만 바꾼 무한 재시도를 하지 않는다.
- 한 장의 외형 실패: 해당 장만 같은 원본/레퍼런스로 교정한다. 룩 마스터가 잘못됐다면 버전을 올리고 그 버전을 소비한 결과만 무효화한다.
- 장면 간 불일치: 양쪽 작업자가 따로 수정하지 않는다. root가 원본 경계와 원인을 확정하고 한쪽 또는 양쪽의 담당자에게 정확히 지정한다.
- 영상 동작 실패: 길이 맞추기로 우회하지 않는다. 원본 동작을 유지하는 프레임 기반 처리 경로를 검토한다. 원본 프레임에 동일 색보정·선명도 개선을 적용하는 비생성 경로는 이야기 보존의 대안이지만, 재생성 완료로 표시하지 않는다. 사용자 선택 없이 목표를 바꾸지 않는다.
- 슬롯/도구 제약: 3개 병렬 호출이 실제 지원되지 않으면 같은 소유권을 유지한 채 호출 큐를 1~2개로 낮춘다. 잠금과 합류 조건은 유지한다.
- 브라우저 금지: ffprobe, ffmpeg 추출 프레임, view_image, 정적 비교 HTML, 파일/코드 검사로 검증한다. 실제 브라우저 스크럽 체감 성능은 명시적 브라우저 요청이 있을 때만 확인하며 자동으로 검증됐다고 보고하지 않는다.
- 성능: 영상·장면별 디코딩 오류 0, 기존 수준 GOP, 현재 대비 파일 크기 증가율을 보고한다. 2560 스틸 목표 때문에 전달 파일 크기와 GOP를 무조건 키우지 않는다.
- 승인된 후보라도 실제 교체 전 원본 경로·해시, 기존 수정 내역, 캐시 정책을 다시 확인한다. 버전 경로와 단일 참조 변경 등 복구 가능한 교체 방식을 root가 선택한다. 현재 요청은 설계이므로 이 단계의 실행은 포함하지 않는다.

최종 완료 산출물은 **24장 스틸 및 필요 경계 이미지, 프롬프트·실측 manifest, 같은 시간축의 8개 클립, 현재 소비 계약의 데스크톱/모바일 영상과 포스터, 원본 오디오 보존 증거, 원본/새 영상 비교 문서, 검수 report, 교체·복구 매핑**이다. 정체성·내용·사건·시간 계약 중 하나라도 미달이면 랜딩 교체 후보로 확정하지 않는다.
