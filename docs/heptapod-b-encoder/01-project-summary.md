# Heptapod B Encoder

> 영화 Arrival(2016)의 외계 문자 체계를 기반으로, 입력한 이름을 헵타포드 B 스타일 로고그램으로 변환하는 인터랙티브 웹 프로젝트.

## 배경 및 목적

- **문제/기회**: 헵타포드 B에는 표음 대응 체계가 없어 이름의 "음역(번역)"은 원리적으로 불가능하다. 이 한계를 숨기지 않고 "번역기"가 아닌 **결정론적 인코더**로 포지셔닝하면, 영화 설정(이름 = 하나의 사고 단위)과도 부합하고 컨셉적으로도 더 강해진다.
- **포지셔닝**: "그럴듯한 가짜 번역기"(바이럴 유리, 수명 짧음)가 아니라 **헵타포드 B의 설계 원리를 체험하는 인터랙티브 에세이**로 간다. 제작 비하인드(reverse-engineering 서사)를 함께 풀어 콘텐츠 자산으로서 수명을 확보한다.
- **기대 효과**:
  - 이름이라는 친숙한 입력을 통해 비선형·동시성이라는 추상 개념을 체감
  - 결정론(같은 이름 → 같은 로고그램)을 공유 가치의 전제로 활용 (URL 재현)
  - 절차적 생성 + 잉크 질감 렌더링이라는 기술 데모로서의 포트폴리오 가치

## 핵심 기능

| # | 기능 | 설명 | 우선순위 |
|---|------|------|---------|
| 1 | 이름 → 결정론적 파라미터 인코딩 | 이름 문자열 해시(xmur3) → 시드 PRNG(sfc32)로 모든 형태 변수 결정. 한글은 NFD 자모 분해로 정보량 확보 | 필수 |
| 2 | 형태 모델 (파라미터 구조) | 링/슬롯/가지(4종)/잉크고임/스플래터/의문형 갈고리를 데이터로 정의. 인코딩·렌더러와 분리 | 필수 |
| 3 | SVG 렌더러 (MVP) | 폴리곤 리본으로 가변 굵기 스트로크 구현, feTurbulence+feDisplacementMap로 잉크 번짐, 다층 path opacity로 농담 | 필수 |
| 4 | 로고그램 챔버 UI | 정방형 + 서리 유리 질감 + 안개 배경(노이즈 레이어). 저채도 모노크롬 무드 | 필수 |
| 5 | 데이터 리드아웃 | 시드 해시·NFD 유닛 수·활성 세그먼트 수·무게중심 각도·12슬롯 상태를 모노스페이스로 표기 | 필수 |
| 6 | 정직한 푸터 카피 | "번역이 아니라 인코딩"이라는 사실 명시 | 필수 |
| 7 | 분석 오버레이 토글 | 울프럼 분석 화면 오마주 — 12세그먼트 분할선·활성 슬롯 마커·유형 코드 표기 | 필수 |
| 8 | 의문형 갈고리 토글 | 본체와 분리된 시드 스트림으로 토글해도 본체 형태 불변 | 선택 |
| 9 | PNG 고해상도 저장 + URL 공유 | canvas toBlob 추출, URL 쿼리에 이름 인코딩(결정론으로 재현) | 선택 |
| 10 | 입자 형성 애니메이션 (Canvas 2D) | 파리 떼 모션 — 개별 jitter + 군집 응집(단순 boids). 완성 후 가장자리 영구 미세 진동. 영화 핵심 무드의 본질 | 필수 |
| 11 | WebGL 유체 렌더링 (3단계) | Navier-Stokes 기반 유체 시뮬레이션에 로고그램 형태를 밀도 소스로 주입. 현실적 잉크 응집·확산 표현의 최고 완성도 목표 | 필수 |
| 12 | 접근성 (prefers-reduced-motion) | 형성 애니메이션 생략, 즉시 완성 표시 | 필수 |

## 대상 사용자

- **주요 사용자**: 영화 Arrival 팬, 절차적 생성/제너러티브 아트 관심층, 자기 이름의 시각화를 공유하고 싶은 일반 사용자
- **보조 사용자**: 디자인 시스템/언어 디자인 사례에 관심 있는 디자이너·개발자 (제작 비하인드 콘텐츠 소비층)

## 기술적 범위

- **포함**:
  - 순수 함수 인코딩 엔진 (이름 → 파라미터)
  - 데이터 기반 형태 모델
  - 교체 가능한 렌더러 — **3단계 모두 구현**: SVG(정지·고품질 추출) → Canvas 2D(입자 형성) → WebGL(유체 시뮬레이션)
  - React.js 기반, 외부 라이브러리 최소 (절차적 path/dab 생성 직접 구현). WebGL 유체는 오픈소스 구현체 참고
- **제외**:
  - 완전한 인공어 문법/생성 규칙 (헵타포드 B는 닫힌 시스템 — 어휘 + 느슨한 조합 규칙만)
  - 실제 번역/음역 기능
  - 서버/백엔드, 사용자 계정, 저장 갤러리
- **제약사항**:
  - 모바일 사파리에서 SVG 필터 성능 편차 큼 → 스프라이트 중첩 방식 대안 검증 필요
  - 입자 애니메이션 입자 수 상한(모바일 2~3천 개) 타협점 탐색 필요
  - **WebGL 유체는 모바일 성능·형태 제어 난이도가 급상승** → 디바이스 등급별 렌더러 폴백 전략 필수(저성능 기기는 Canvas/SVG로 우아한 강등)
  - 결정론은 절대 조건 — 같은 이름은 항상 같은 출력
  - 깔끔한 벡터 곡선 금지 — 외곽선 번짐·농담 불균일이 정체성의 절반

## 성공 기준

- 샘플 이름 50개 시각 충돌 테스트 통과 (결정론 유지 + 형태 다양성 충분)
- 잉크 질감이 모바일 사파리에서 깨지지 않음 (렌더러 폴백 포함)
- 정지 이미지 단독으로 "진짜 헵타포드 B 같다"는 인상 확보 (SVG 단계로 달성)
- WebGL 유체 단계에서 잉크의 응집·확산이 현실적 물성으로 표현되고, 데스크톱 기준 60fps 유지
- 디바이스 등급별 렌더러 폴백이 끊김 없이 동작 (WebGL → Canvas → SVG)
- 사용자가 자기 이름과 로고그램의 "규칙이 있어 보이는" 연결을 느낌
