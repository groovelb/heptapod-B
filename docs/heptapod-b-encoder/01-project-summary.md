## 1. 한 줄 요약

> 영화 Arrival의 문자 체계에 끌린 사람이 자기 이름을 소리로 옮기는 대신 하나의 사고 단위로 응축해 보게 하는, 헵타포드 B의 결정론적 인코더.

태그라인: Not translation, but encoding.

---

## 2. 배경과 목적

- **문제 또는 기회**: 헵타포드 B에는 표음 대응 체계가 없어서 이름의 음역은 원리적으로 불가능하다. 이 한계를 숨기고 그럴듯한 번역기를 만들면 바이럴은 되지만 수명이 짧다. 한계를 먼저 밝히고 결정론적 인코더로 포지셔닝하면 원작 설정(이름은 하나의 사고 단위)과도 맞고 컨셉이 더 강해진다.
- **왜 지금, 왜 우리**: 원작의 문자는 연출이 먼저였고 체계는 사후에 정리됐다. 같은 방법으로 우리도 형태를 먼저 관찰해 규칙으로 되돌린다. 그 역설계 과정 자체가 콘텐츠다.
- **기대 효과**: 이름이라는 친숙한 입력으로 비선형과 동시성이라는 추상 개념을 체감시킨다. 같은 이름이 같은 결과를 내는 성질이 공유의 전제가 되어 링크 하나로 재현된다. 절차적 생성과 잉크 질감이라는 기술 시연으로서의 가치도 남는다.

## 3. 정체성

### 3.1 핵심 가치 (최대 3)

| 이름 | 한 줄 | 반대말 (하지 않는 태도) |
|---|---|---|
| Honesty (정직) | 번역이 아니라 인코딩이라고 먼저 말한다 | 그럴듯하게 꾸민 가짜 번역기 |
| Determinism (결정론) | 같은 이름은 언제나 같은 형태가 된다 | 부를 때마다 달라지는 생성물 |
| Stillness (정적) | 낮은 드론처럼 가라앉은 페이싱 | 서두르는 반응, 과한 자극 |

### 3.2 태도 키워드 (최대 5, 단어만)

정직함 · 절제 · 정적 · 몽환적 · 차가움

### 3.3 포지셔닝 (선택)

| 축 | 우리의 선택 | 반대 축 |
|---|---|---|
| 제품 성격 | 설계 원리를 체험하는 인터랙티브 에세이 | 한 번 쓰고 마는 밈 생성기 |
| 커뮤니케이션 | 한계를 먼저 밝히는 정직한 카피 | 번역이라고 말해 버리는 과장 |
| 결과물 | 링크만으로 재현되는 하나의 형태 | 매번 달라지는 무작위 이미지 |
| 관객 관계 | 만드는 방법까지 열어 보이는 관계 | 결과만 보여 주는 블랙박스 |

## 4. 사용자와 다루는 대상

### 4.1 사용자

| 이름 | 누구인가 | 무엇을 원하나 | 주/보조 |
|---|---|---|---|
| 영화 팬 | 원작의 문자 체계에 끌린 관객 | 자기 이름의 형태, 공유할 결과 | 주 |
| 제너러티브 관심층 | 절차적 생성을 보는 창작자 | 규칙과 파라미터의 구조 | 주 |
| 디자이너·개발자 | 언어 디자인 사례를 찾는 실무자 | 역설계 방법론과 정직한 한계 | 보조 |

### 4.2 다루는 대상

| 이름 | 식별자 | 한 줄 정의 | 만드는 주체 | 개수 |
|---|---|---|---|---|
| 입력 이름 | EncodeInput | 인코딩할 이름 문자열과 의문 표시 | 사용자 | 하나 |
| 시드 | Seed | 이름에서 얻은 수와 자모 단위 목록 | 시스템 | 하나 |
| 로고그램 모델 | LogogramModel | 링·슬롯·가지·덩어리의 기하 값 | 시스템 | 하나 |
| 데이터 리드아웃 | Readout | 화면에 표기하는 계측값 묶음 | 시스템 | 하나 |
| 렌더 설정 | RenderConfig | 표현 품질 등급과 감속 모션 여부 | 시스템 | 하나 |
| 인트로 비트 | HeroBeat | 인트로 한 마디의 카피와 길이 | 제작자 | 몇 개 |

비고: 개수 값은 하나 / 몇 개 / 많음이다. 시드와 모델과 리드아웃은 입력 이름에서 파생되므로 사용자가 직접 만들지 않는다.

## 6. 범위와 성공 기준

- **포함**: 이름을 형태 값으로 바꾸는 규칙, 형태의 데이터 모델, 형태를 되읽어 이름을 복원하는 경로, 기기 성능에 따른 표현 품질 단계, 세계관 인트로, 소리, 결과 저장과 링크 공유 (잠정)
- **제외**: 완전한 인공어 문법과 생성 규칙 · 실제 번역과 음역 · 서버와 사용자 계정 · 저장 갤러리 · 다국어 지원
- **제약**: 결정론은 절대 조건이다 · 서버 없이 사용자의 브라우저 안에서 끝난다 · 기기 성능이 낮아도 형태 자체는 같아야 한다 · 원작 음원을 그대로 쓰지 않는다 · 소리는 사용자의 첫 상호작용에서 시작된다 · 일부 모바일 브라우저는 질감 표현의 성능 편차가 크다 · 움직이는 점은 모바일에서 2~3천 개가 상한이다 · 표현 품질 최상위 단계는 모바일에서 성능과 제어 난이도가 급해진다 (잠정)

표본 점검과 인터뷰는 제안값이고, 결정론과 재현은 검증 스크립트로 확인한다.

| 성공 기준 | 확인 방법 |
|---|---|
| 같은 이름이 언제나 같은 형태로 나온다 | 모델 회귀 검증 스크립트 |
| 표본 이름 50개가 서로 구분된다 | 검증 스크립트의 충돌 점검 |
| 형태를 되읽으면 원래 이름이 나온다 | 복원 값과 입력 값 대조 |
| 링크만으로 같은 결과가 재현된다 | 공유 주소 재진입 확인 |
| 규칙이 있어 보인다는 인상이 남는다 | 과업 3 관찰 기록 (잠정, Q1) |
| 낮은 성능 기기에서도 질감이 깨지지 않는다 | 기기별 표본 확인 (잠정, Q1) |
| 정지 화면만으로 진짜 문자 같다는 인상 | 첫인상 인터뷰 (잠정, Q1) |
| 표현 품질 단계가 끊김 없이 낮아진다 | 등급별 진입 확인 (잠정, Q1) |
| 최상위 표현이 데스크톱에서 초당 60프레임 | 성능 계측 (잠정, Q1) |

비고: 앞의 네 기준은 검증 스크립트와 화면 표기로 확인할 수 있고, 뒤의 다섯 기준은 사람의 관찰이나 기기별 계측이 필요하다. 뒤의 네 기준과 마지막 제약 세 개는 원문 01의 성공 기준·제약에서 되살린 것이다.
